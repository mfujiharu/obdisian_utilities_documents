# 概要
本ノートは `project_type: 執筆` が指定されたプロジェクトに適用される詳細ルールである。
# フォルダ構造（執筆）
執筆プロジェクトのプロジェクトフォルダには以下を置く。
- プロジェクトフォルダ/
	- **プロジェクト管理ノート:** `プロジェクト名.md`
	- `index.md`
	- `Temp/`
		- **コンテキストノート**
	- `Settings/`
		- **設定ノート**
	- `Chapters/`
		- **全体構成ノート**: `全体構成.md`
		- `企画1/`　（以下、`企画2/`、`企画3/` と続く）
			- **作業ノート**
			- **プロットノート**
			- **本文**
		- `1話/`　（以下、`2話/`、`3話/` と続く）
			- （`企画1/`とフォルダ内構成は同じ）
		- `1巻/`　（以下、`2巻/`、`3巻/` と続く）
			- （`企画1/`とフォルダ内構成は同じ）
		- `コミック1/`　（以下、`コミック2/`、`コミック3/` と続く）
			- （`企画1/`とフォルダ内構成は同じ）
		- `YYYYMM_*`（日付順に続く）
			- （`企画1/`とフォルダ内構成は同じ）
		- `完了/`
	- `Books/`
		- `Web資料/`
		- **資料ノート**
	- `Contract/`
		- 契約書（Obsidianでは扱わない）
## 1.プロジェクト管理ノート
Frontmatterの詳細は、[[Utilities/Documents/詳細設計/データ整理ルール#Frontmatterパラメータ定義|データ整理ルール]]を参照せよ。
本文には以下などを書く。
- あらすじ
- キャラクター一覧
- 設定項目一覧
## 2. index.md
[OKF SPEC](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md) に基づき、目次・ディレクトリ構成マップを置く。
## 3. `Temp/`
AIへの問い合わせ用の**コンテキストノート** を保管しておく。
本ノートはスクリプトが定期的に上書きするため、ユーザーは直接編集しないこと。
## 4. `Settings/`
**設定ノート**を置く。

設定ノートのノート名は、**プロジェクト管理ノート**の以下の項に記載されたタグ名と一致する。
設定ノートを操作する際は、プロジェクト管理ノートの以下のセクションからタグを抽出する。書式に従っていない場合のみ、AIによる解析にフォールバックする（[[Utilities/Documents/詳細設計/共通設定・モジュール仕様#2 ローカル処理優先・AIはフォールバック|AI問い合わせモジュール]]参照）。
- キャラクター一覧
- 設定項目一覧
## 5. `Chapters/`
- **全体構成ノート**： `全体構成.md`
- 作業フォルダ
- `完了/`
	- 作業フォルダ（作業済）
を置く。

`status: false`の作業ノートを含む作業フォルダは、`完了/`へ移動させる。移動はユーザが行うので、AIの操作は不要。
### 1. 作業フォルダ （例： `1話/`、`コミック1/`）
作業フォルダは以下の作業単位ごとに作成し、ナンバリングを振る。
- `企画` → `企画1`、`企画2`と続く
- `話`→ `1話`、`2話`と続く
- `巻`→ `1巻`、`2巻`と続く
- `コミック`→ `コミック1`、`コミック2`と続く
- `YYYYMM_*` →　`YYYYMM_キャラ`、`YYYYMM_イベント`等、日付順に続く

※`企画`、`話`、`巻`、`コミック`、`YYYYMM_`はそれぞれ独立した作業単位であり、包含関係を持たない。
（例： `1巻`の内容が`1話`～`3話`に対応するとは限らない）
※プロジェクト管理ノートの`category`の値とこの作業単位に相関関係はない。

作業フォルダの下には、
- **作業ノート**： 作業フォルダにつき1つ
- **プロットノート**： 同一作業フォルダ内に複数存在
- **本文**： 同一作業フォルダ内に複数存在
- その他、Markdown以外のファイル（Obsidianでは扱わない）
を置く。

作業ノート・プロットノート・本文に命名規則はなく、Frontmatteの`type`で判別する。
複数あるプロットノート・本文をAIに操作させる際は、別途、ノートを特定するための指示を加える。
## 6. `Books/`
外部からインポートした資料などを置く。
## 7. `Contracts/`
契約書などを置く。Obsidianでは扱わない。
## 8. 除外フォルダ
以下のフォルダは、AIでの読み取りも編集も不可。
- `Contracts/`以下

以下のフォルダ以下のノートは、AIの読み出しは可だが編集は不可。
- `Chapters/完了/`以下
- `Books/`以下
# Frontmatterパラメータ定義
`project_type: 執筆`内の固有のフィールドの意味・許容値を定める。
全プロジェクト共通の項目については、[[Utilities/Documents/詳細設計/データ整理ルール#Frontmatterパラメータ定義|データ整理ルール]]を参照。

| フィールド            | 意味                  | 許容値・書式                                                                  | 適用対象`type`                                                   | 必須/任意 |
| ---------------- | ------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------ | ----- |
| category         | プロジェクトの区分           | `小説`/`漫画原作`/`ゲームシナリオ`                                                   | `プロジェクト管理ノート`                                                | 必須    |
| project_name     | プロジェクトの名前           | 自由記述                                                                    | `プロジェクト管理ノート`                                                | 必須    |
| project_link     | 所属プロジェクト            | プロジェクト管理ノートへのリンク                                                        | `設定ノート`/`全体構成ノート`/`作業ノート`/`プロットノート`/`本文`/`資料ノート`/`コンテキストノート` | 必須    |
| type             | ノートの種別              | `プロジェクト管理ノート`/`設定ノート`/`全体構成ノート`/`作業ノート`/`プロットノート`/`本文`/`資料ノート`/`コンテキストノート` | 全部                                                           | 必須    |
| episode          | 話数、巻数などの識別番号        | 作業フォルダ名と一致                                                              | `作業ノート`/`プロットノート`/`本文`                                       | 必須    |
| version          | バージョン番号             | 整数（1から開始）。<br>未設定時は`1`として扱う。                                            | `プロットノート`/`本文`                                               | 任意    |
| status           | 進行中か否か              | `true`/`false`                                                          | `プロジェクト管理ノート`/`作業ノート`                                        | 必須    |
| final            | 提出品（完成稿）かどうかのフラグ    | `true`/`false`<br>未設定時には`false`として扱う。                                   | `プロットノート`/`本文`                                               | 任意    |
| aliases          | Obsidianの別名（検索・言及用） | AI用問い合わせ名を設定する                                                          | `コンテキストノート`                                                  | 必須    |
| source_signature | 集約対象ノート群の差分検知用シグネチャ | 各集約対象ノートの相対パスと`updated`の組をソート・結合した値                                     | `コンテキストノート`                                                  | 必須    |
# 各ノートの構造
各ノートとも自由記述セクションは平文（通常のMarkdown段落）を許可する。**設定ノート**、**全体構成ノート**、**作業ノート**では平文の他、Markdownの箇条書きのノードにインラインタグを付与して擬似的な文脈構造を持たせる。
## 1. 設定ノート（`type: 設定ノート`)のタグ構造
ノード最上位の `#プロジェクト名` には、実際のプロジェクト名（例: `#今世は悪女`）を付与する。
`#プロジェクト名`の子ノードは、**設定ノート名と一致する**。

- #プロジェクト名 
	- #キャラ名 
		- #メモ 
		- #保留 
	- #世界設定 
		- （`#キャラ名`と同じツリー構造）
	- #資料
		- （`#キャラ名`と同じツリー構造）
## 2. 全体構成ノート（`type: 全体構成ノート`)のタグ構造
ノード最上位の `#プロジェクト名` には、実際のプロジェクト名（例: `#今世は悪女`）を付与する。

- #プロジェクト名 
	- #全体構成 
		- #メモ 
		- #打ち合わせ 
		- #展開案 
		- #1巻 / #2巻 / #3巻 （以下、話ごとのツリー）
		- #1話 / #2話 / #3話 （以下、話ごとのツリー）
## 3. 作業ノート（`type: 作業ノート`)のタグ構造
ノード最上位の `#プロジェクト名` には、実際のプロジェクト名（例: `#今世は悪女`）を付与する。
`#プロジェクト名`の子ノードのタグは、直上の作業フォルダ名と一致する。（例： `#企画1`）

作業ノートのタグ構造は、プロジェクト管理ノートの`category`ごとに異なる。
### A. 小説 (`category: 小説`)
- #プロジェクト名 
	- #作業フォルダ名
		- #メモ 
		- #打ち合わせ 
		- #展開案 
		- #プロット
			- #メモ 
			- #1章 
			- #2章　（以下、章ごとのツリー）
		- #草稿 （`#プロット` と同じツリー構造）
		- #初稿 （`#プロット` と同じツリー構造）
		- #初稿殴り書き （`#プロット` と同じツリー構造）
		- #初稿清書 （`#プロット` と同じツリー構造）
		- #改稿（`#プロット` と同じツリー構造）
### B. 漫画原作 (`category: 漫画原作`)
- #プロジェクト名 
	- #作業フォルダ名
		- #メモ 
		- #打ち合わせ 
		- #展開案 
		- #プロット 
		- #草稿 
		- #初稿殴り書き 
		- #初稿清書 
		- #改稿 
		- #三稿 
		- #四稿 
### C. ゲームシナリオ (`category: ゲームシナリオ`)
（※検討中）
## 4. プロットノート（`type: プロットノート`)
プロットノートは箇条書き構造とタグを持たず、Frontmatterでのみ管理される。
`final`と`version`の更新はユーザが行うので、AIは操作不要。

プロットノート・本文のうち、整合性チェックなどAIによる文脈判定に用いる際は、`final: true`のノート（提出品）のみを対象とし、 `final: false`または未設定のノート（下書き）は参照しない。 （ただしユーザーから明示的な指示があった場合はこの限りではない）
またプロットノートと本文の`final`は独立しており、一方が`true`でも他方が`true`とは限らない。

また同一作業フォルダ内に複数のプロットノート・本文が存在する状態が常態化するため、 これらをAIに操作させる際は、`final`および`version`の値をあわせて指定するなど、 別途、対象ノートを特定するための指示を加える。
## 5. 本文（`type: 本文`)
本文は箇条書き構造とタグを持たず、Frontmatterでのみ管理される。
運用ルールはプロットノートのセクションを参照のこと。
## 6. 資料ノート（`type: 資料`)
資料ノートは箇条書き構造とタグを持たず、Frontmatterでのみ管理される。
## 7. コンテキストノート（`type: コンテキストノート`）
本ノートはスクリプトが定期的に上書きするため、ユーザーは直接編集しないこと。
Frontmatterに`aliases`（プロジェクト名）を設定し、Gemini Scribeから短縮形でアクセスできるようにする。
