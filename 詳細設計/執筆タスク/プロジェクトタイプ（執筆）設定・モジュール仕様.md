# 本ノートの目的
[[Utilities/Documents/基本設計/基本設計#詳細設計ノート一覧|基本設計]]に基づき、`project_type: 執筆`に固有の設定値・モジュール関数の詳細をまとめる。
# 設定ファイル（`config/project_types/writing.yaml`）
```
writing:
  skip_tag: "転記済"                 # 転記処理スキップ判定に用いるタグ
  settings_fallback_node: "保留"     # 設定ノート追記時のフォールバックノード名
  fallback_section: "メモ"           # 作業ノート追記時、該当セクションがない場合の既定セクション名
```
# モジュール（`modules/project_types/writing.py`) 
`project_type: 執筆`のプロジェクトに固有の処理を担う。
最低限、以下の機能を持つこと。
## プロジェクト管理ノートから、設定ノート用のタグを取得する
プロジェクト管理ノートの「キャラクター一覧」「設定項目一覧」の項からタグを取得する。
[[スポット/Pythion開発/（旧）共通設定・モジュール仕様#2 ローカル処理優先・AIはフォールバック|AI問い合わせモジュールの運用ルール]]に従い、まず定められた軽量書式（[[Utilities/Documents/詳細設計/執筆タスク/データ整理ルール（執筆）#4. `Settings/`|データ整理ルール（執筆）]]参照）に沿ったローカル解析を試み、書式に従っていない場合や抽出結果が空になる場合にのみAIにフォールバックする。
## 転記処理スキップ判定
ノード内のタグを抽出し、`#skip_tag`を除外した上で、設定ノートまたは作業ノートとして解決できる転記先候補をフルパスで重複排除する。
- `#skip_tag`を含む：転記済みとしてスキップ
- 転記先候補0件：転記先なしとしてスキップ
- 転記先候補1件：その候補へ転記
- 転記先候補2件以上：転記先を一意に確定できないためスキップ
タグの出現順、ファイル名、`updated`等で自動選択しない。スキップ時は転記元、対象ノード、抽出タグ、候補パス、理由をログへ記録し、ほかのノードは継続する。
## 設定ノートの検出
**プロジェクト名**、**ノート名（空欄を認める。`#`を含むタグ文字列。例：`#アナスタシア`）** を引数として受け取り、`Settings/`以下から該当する設定ノートを探す。
- `Settings/`以下に存在する
- プロジェクト管理ノートから取得した設定ノート用のタグ名と一致する

ノート名が上の条件を満たした場合は、設定ノートのフルパスを返す。
引数のノート名が空欄だった場合は、該当する設定ノートのフルパスを配列で返す。
どちらにも該当しなければ`None`を返す。

- 例1： `転生女帝` + `#アナスタシア`　→ `Settings/アナスタシア.md`
- 例2： `転生女帝` + `#世界設定`　→ `Settings/世界設定.md`
## 作業ノートの検出
`project_name`、`note_name`、`status: bool | None`を受け取り、`Chapters/`以下から作業ノートを検索する。`完了/`等の配置場所は判定に使用しない。
- `status=None`：`status`を問わず検索
- `status=True`：`status: true`のみ
- `status=False`：`status: false`のみ
転記先検索では呼び出し元が必ず`status=True`を指定する。読み取り検索ではタスクの目的に応じていずれかを指定する。
### 全体構成ノート
ノート名が`全体構成`で、`type: 全体構成ノート`として一意に検出できるものを返す。複数件ならERRORとして返さない。
### 作業フォルダの作業ノート
作業フォルダごとに`type: 作業ノート`かつ指定された`status`条件に一致する件数を確認する。
- 0件：WARNINGを記録し、その作業フォルダをスキップ
- 1件：フルパスを返す
- 2件以上：ERRORとし、全候補パスを記録してその作業フォルダをスキップ
ファイル名、更新日時、走査順で自動選択しない。1フォルダの異常でほかの正常なフォルダの処理を止めない。
## 設定ノートへ追記する
1. 転記先の設定ノートを開く。
2. `#プロジェクト名` > `#子ノードのタグ` > `#settings_fallback_node`のノードを含む箇条書きツリーを検索する。
3. ノードが欠けている場合は、新規に不足ノードを追記する。
	1. `#プロジェクト名` > `#子ノードのタグ`のツリーがある場合： 下に`#settings_fallback_node`のノードを追記する。
	2. `#プロジェクト名`のツリーがある場合： 下に `#子ノードのタグ` > `#settings_fallback_node`のノードを追記する。
	3.  `#プロジェクト名`のツリーがない場合： 
		1. 設定ノートの末尾に、新規に`#プロジェクト名`の箇条書きツリーを追記する。
		2. その下に、 `#子ノードのタグ` > `#settings_fallback_node`のノードを追記する。
4. コピーしたブロックから、`#子ノードのタグ`を含むノードを削除する。
5. 加工したブロックを、`#settings_fallback_node`の子ノードとして、インデントレベルを揃えて追記する。

※ここでの`#子ノードのタグ`には、「設定ノートの検出」呼び出し時に渡した（あるいはそれによって特定された）ノート名タグをそのまま用いること。

2. `#プロジェクト名` > `#子ノードのタグ`を含む箇条書きツリーを探す。

4. コピーしたブロックから、`#子ノードのタグ`を含むブロックを削除する。
5. 該当するタグセクション（例: `#メモ` や `#1話`）の**一番下の子ブロック（配下の末尾）** に改行を入れて、インデントのレベルを調整（該当セクションの子要素として揃える）しながら追記する。
6. 該当するタグセクションが複数ある場合は、最後に出現したタグセクションの末尾に追記する。
7. 該当するタグセクションがない場合は、`fallback_section`で指定されたセクション（既定値：`#メモ`）の末尾へ同様に追記する。
## `get_tag_schema(category)`
プロジェクト管理ノートの`category`（`小説`/`漫画原作`/`ゲームシナリオ`）に応じたタグ階層定義を返す（[[Utilities/Documents/詳細設計/執筆タスク/データ整理ルール（執筆）|データ整理ルール（執筆）]]の「作業ノートのタグ構造」参照）。
## `is_excluded(path)`
`Books/`・`Contract/`など、執筆プロジェクト固有の除外フォルダに該当するかどうか、および読み取りのみ可か編集も不可かを判定する（[[Utilities/Documents/詳細設計/執筆タスク/データ整理ルール（執筆）#8. 除外フォルダ|データ整理ルール（執筆）]]参照）。
# 転記の一方向性
転記は一度限りの一方向コピーとする。`#skip_tag`が付いたブロックは、後から編集されても再転記、差分同期、置換を行わない。追加で反映する内容は、ユーザーが新しい未転記ブロックとして作成する。転記シグネチャは持たせない。
