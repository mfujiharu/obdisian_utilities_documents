# タスクの概要
本タスクは`project_type: 執筆`用のタスクである。
デイリーノートから、執筆プロジェクトに関する作業メモ・アイデア・設定を読み取り、ルールに従って該当する「作業ノート（`Chapters/`以下）」または「設定ノート（`Settings/`以下）」へ振り分けてコピー・追記する。
# 前提条件
スクリプトの実行環境、前提条件、基本ルールは、[[Utilities/Documents/基本設計/基本設計|基本設計]]を参照のこと。
# タスク名
本個別タスクのタスク名は「**organize_daily**」とする。
# 本タスク用設定ファイル
本タスク用の設定ファイルには、以下を記述する。
（ファイルパス：`config/tasks/organize_daily.yaml`）
```
organize_daily:
  use_ai: true 
  lookback_days: 3                    # デイリーノートを遡って確認する日数
```
`skip_tag`・`settings_fallback_node`は、`project_type`（本タスクでは`執筆`）ごとの規約値のため、[[Utilities/Documents/詳細設計/執筆タスク/プロジェクトタイプ（執筆）設定・モジュール仕様|プロジェクトタイプ（執筆）設定・モジュール仕様]]を参照する。
# 整理・抽出手順
## 1. 設定ファイルの読み込み
## 2. 対象プロジェクトの抽出
[[Utilities/Documents/詳細設計/共通設定・モジュール仕様#プロジェクト探索モジュール（`project_discovery.py`）|プロジェクト探索モジュール]]の`find_projects()`を用い、以下を満たすプロジェクトを検出する。
- `project_type: 執筆`
- `status: true`
- `ai_check: true`

同時に**プロジェクト名（=`project_name`）** を取得する。
## 3. デイリーノート内から転記対象ブロックを抽出
### 1. 実行日の日付を取得
`config.yaml`の`run.target_date_source`の設定に従い、実行日の日付を取得する。
- `arg`：コマンドライン引数`--date`の値を実行日とする（例：`--date 2026-07-30`）。
- `env`：環境変数から取得する。
- `auto`：実行時のシステム日付（`timezone: Asia/Tokyo`）から自動算出する。

取得した日付を、以降の遡り処理における基準日（実行日）とする。
### 2. 遡る日数を取得
本タスク設定ファイル（`config/tasks/organize_daily.yaml`）の`lookback_days`の値を取得する。
### 3. 対象デイリーノートを特定
実行日の前日から`lookback_days`で指定された日数分だけ日付を遡り、`config.yaml`の`daily_folder`（既定値：`DailyNote/`）以下から該当日付のデイリーノートを特定する。
- 該当日付のファイルが存在しない場合は、その日をスキップする（エラーとしない）。

（例：実行日が2026-07-30、`lookback_days: 3`の場合、2026-07-27・2026-07-28・2026-07-29の3件が対象となる。）
### 4. デイリーノートから`#プロジェクト名`のツリーを抽出する
デイリーノートをMarkdown構造で解析し、箇条書きツリーから対象プロジェクトの `#プロジェクト名`（例: `#今世は悪女`）以下のブロックを抽出する。
複数日のデイリーノートを処理する際は、日付が古いノート（3日前）から順に走査を行うこと。
### 5. 抽出したブロックの子ノードの解析
抽出したブロックの、`#プロジェクト名`の**子ノード**を順番に、以下の手順で判定していく（判定関数は[[Utilities/Documents/詳細設計/執筆タスク/プロジェクトタイプ（執筆）設定・モジュール仕様|プロジェクトタイプ（執筆）設定・モジュール仕様]]参照）。
1. 転記処理スキップ判定：当てはまった場合は処理をスキップする。
2. 子ノードのタグを引数に「設定ノートの検出」を呼ぶ：パスが返れば、それを転記先とする。
3. 2で`None`が返った場合、子ノードのタグと`status: true`を引数に「作業ノートの検出」を呼ぶ：パスが返れば、それを転記先とする。
4. 2・3のいずれも`None`だった場合は、処理をスキップする。
## テキストをコピーする
合致した子ノードのブロック（**子や孫ノードも含めた、配下にある全ての箇条書き**）を、階層構造を維持したまま一括コピーする。
## 特定したノートに追記する
転記先が設定ノートの場合と作業ノートの場合とで、追記方法が異なる（[[Utilities/Documents/詳細設計/執筆タスク/プロジェクトタイプ（執筆）設定・モジュール仕様#設定ノートへ追記する|プロジェクトタイプ（執筆）設定・モジュール仕様]]の「設定ノートへ追記する」「作業ノートへ追記する」をそれぞれ参照）。
## 重複転記防止処理（デイリーノート側の更新）
二重処理防止および参照追跡のため、デイリーノート側の子ノードに`#skip_tag`を記載する。
- フォーマット: `#子ノードのタグ` ▶  [[転記先ノートへのフルパス]] へ `#skip_tag`
# 処理実行の具体例
以下は、プロジェクト「今世は悪女」（`project_type: 執筆`、`project_name: 今世は悪女`、`status: true`、`ai_check: true`）を例にした一連の流れである。

**前提**
- 実行日：2026-07-30、`lookback_days: 3` → 対象デイリーノートは2026-07-27・2026-07-28・2026-07-29の3件（古い日付から順に処理）。
- 2026-07-29のデイリーノートに以下の記述があるとする。

```
- #今世は悪女
	- #シルヴィア
		- 侯爵家の令嬢。ヒロインの婚約者。
	- #1話
		- #プロット
			- 主人公の前世の説明からスタートする案。
```

**判定・転記**
1. `#今世は悪女`ブロックを抽出する。
2. 子ノード`#シルヴィア`：付与タグは`#シルヴィア`の1個 → 「設定ノートの検出」に合致。`Settings/シルヴィア.md`が存在するため、転記先はこのノートとなる。
3. 子ノード`#1話`：付与タグは`#1話`の1個 → 「設定ノートの検出」では`None`。「作業ノートの検出」に合致し、`Chapters/1話/`直下に作業ノートが1つ、`status: true`のため、転記先は`Chapters/1話/1話作業ノート.md`となる。

**転記結果**
- `Settings/シルヴィア.md`：`#今世は悪女 > #シルヴィア`のツリーが既にある場合、その下位の`#保留`ノードの子として「侯爵家の令嬢。ヒロインの婚約者。」を追記する。
- `Chapters/1話/1話作業ノート.md`：`#プロット`セクションの末尾に「主人公の前世の説明からスタートする案。」を追記する。

**デイリーノート側の更新結果**
```
- #今世は悪女
	- #シルヴィア ▶ [[Settings/シルヴィア]] へ #転記済
		- 侯爵家の令嬢。ヒロインの婚約者。
	- #1話 ▶ [[Chapters/1話/1話作業ノート]] へ #転記済
		- #プロット
			- 主人公の前世の説明からスタートする案。
```
