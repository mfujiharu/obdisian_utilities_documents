# タスクの概要
本タスクは`project_type: 執筆`用のタスクである。
執筆中のプロット・本文と、過去に執筆した（作業完了した）プロット、本文、設定を比較するための文脈資料（コンテキストノート）を用意し、AI（Gemini Scribe）との対話を通じて矛盾点等のコメントを得られるようにする。
# 前提条件
本タスクは、
- Gemini Scribe（Obsidianのコミュニティプラグイン。[[Utilities/Documents/詳細設計/Python実行環境・AIエージェント情報|Python実行環境・AIエージェント情報]]参照）
- Pythonスクリプト

を併用して実装する。

Pythonスクリプトの実行環境、前提条件、基本ルールは、[[Utilities/Documents/基本設計/基本設計|基本設計]]を参照のこと。

本タスクのうちPythonスクリプトが担うのは、後述「整理・抽出手順」（コンテキストノートの生成）のみである。この工程は通常のバッチ処理として`main.py --task coherence_check`から実行し、CLIエントリーポイント・実行モード（dry_run/execute）・スナップショット規定など、開発ルールの共通ルールに従う。

生成後にGemini Scribeで行う対話（後述「Gemini Scribeでの問い合わせ方法」）は、ユーザーがその場で行う対話的な作業であり、[[Utilities/Documents/詳細設計/共通設定・モジュール仕様#AI問い合わせモジュール（`ai_client.py`）|AI問い合わせモジュール]]の各規定（呼び出し粒度の原則・JSON出力形式の統一・フォールバック規定・キャッシュ）の対象外とする。これらの規定はスクリプトが自動的に発行するAI問い合わせを対象としたものであり、ユーザーが対話的に行うチャットには適用されない。
# タスク名
本個別タスクのタスク名は「**coherence_check**」とする。
# 本タスク用設定ファイル
本タスク用の設定ファイルには、以下を記述する。
（ファイルパス：`config/tasks/coherence_check.yaml`）
```
coherence_check:
  use_ai: false   # コンテキストノートの生成はPythonのみで行い、AIは使用しない
```
# 整理・抽出手順
## 1. 設定ファイルの読み込み
## 2. 対象プロジェクトの抽出
[[Utilities/Documents/詳細設計/共通設定・モジュール仕様#プロジェクト探索モジュール（`project_discovery.py`）|プロジェクト探索モジュール]]の`find_projects()`を用い、以下を満たすプロジェクトを検出する。
- `project_type: 執筆`
- `status: true`
- `ai_check: true`

同時に **プロジェクト名（=`project_name`）** を取得する。
## 3. 集約対象ノートを選定する（本タスク固有の条件）
以下の条件でノートを選定する。この選定条件は本タスク固有であり、モジュール側には持たせない。
- プロジェクト管理ノート：無条件で含める
- 設定ノート：`Settings/`内の全ノート
- 作業ノート：[[Utilities/Documents/詳細設計/執筆タスク/プロジェクトタイプ（執筆）設定・モジュール仕様#作業ノートの検出|プロジェクトタイプ（執筆）設定・モジュール仕様]]の「作業ノートの検出」に、プロジェクト名・（ノート名は空欄）・`status: false`を渡して検出したもの
- プロットノート：`final: true`のもの
- 本文：`final: true`のもの
## 4. ノートを結合し、コンテキストノートとして保存する
[[Utilities/Documents/詳細設計/共通設定・モジュール仕様#複数ノートを結合して保存する|Markdown / Frontmatter入出力モジュール]]の`combine_notes()`を用いて、ステップ3で選定したノート群を結合し、コンテキストノートとして保存する。
- `note_paths`：ステップ3で選定したノートパス一覧
- `exclude_tags`：`#メモ`（設定ノート・作業ノートの本文からこのタグのノードを配下ごと除外する）
- `output_path`：プロジェクトフォルダ直下の`Temp/コンテキスト.md`（[[Utilities/Documents/詳細設計/データ整理ルール（執筆）|データ整理ルール（執筆）]]参照）
- `frontmatter`：`type: コンテキストノート`、`aliases: プロジェクト名`

`combine_notes()`側で差分チェック（`source_signature`の比較）が行われ、対象ノート群に変更がなければ書き込みがスキップされる。

このコンテキストノートは定期的に（バッチ実行等で）再生成しておき、Gemini Scribeでの問い合わせ時の処理負荷を減らす。
# Gemini Scribeでの問い合わせ方法
Gemini Scribeのチャット画面から以下のプロンプトで問い合わせる。

例：
```
@Active File と @プロジェクト名　を比較して、矛盾点を指摘して
```

プロンプトはユーザがタスクに応じてその場で書くので（あるいはGemini Scribeに定型文として登録するので）、スクリプトで作成はしない。
