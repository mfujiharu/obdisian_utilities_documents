# タスクの概要
本タスクは`project_type: 執筆`用のタスクである。
`Chapters/`以下の作業ノートをAIを用いて解析し、執筆作業と無関係なメモ・雑記・タスク等を切り出してデイリーノートへ移動（作業ノートからは削除）する。
# 前提条件
スクリプトの実行環境、前提条件、基本ルールは、[[Utilities/Documents/基本設計/基本設計|基本設計]]を参照のこと。
# タスク名
本個別タスクのタスク名は「**cull_settings**」とする。
# 本タスク用設定ファイル
本タスク用の設定ファイルには、以下を記述する。
（ファイルパス：`config/tasks/cull_settings.yaml`）
```
cull_settings:
  use_ai: true
  max_lookback_days: 30   # 転記先デイリーノートを遡って探す際の上限日数（安全装置）
  review_required: false  # 人手確認フェーズを設けずexecuteで直接移動する
```
`#skip_tag`（本タスクではデイリーノート側への転記済マーキングに使用）は、`project_type`（本タスクでは`執筆`）ごとの規約値のため、[[Utilities/Documents/詳細設計/執筆タスク/プロジェクトタイプ（執筆）設定・モジュール仕様|プロジェクトタイプ（執筆）設定・モジュール仕様]]を参照する。
# 整理・抽出手順
## 1. 設定ファイルの読み込み
## 2. 対象プロジェクトの抽出
[[スポット/Pythion開発/（旧）共通設定・モジュール仕様#プロジェクト探索モジュール（`project_discovery.py`）|プロジェクト探索モジュール]]の`find_projects()`を用い、以下を満たすプロジェクトを検出する。
- `project_type: 執筆`
- `status: true`
- `ai_check: true`

同時に **プロジェクト名（=`project_name`）** を取得する。
## 3. 対象作業ノートの検出
[[Utilities/Documents/詳細設計/執筆タスク/プロジェクトタイプ（執筆）設定・モジュール仕様|プロジェクトタイプ（執筆）設定・モジュール仕様]]の「作業ノートの検出」処理を用いて、
- プロジェクト名
- （ノート名は空欄とする）
- `status: true`

を引数として与え、タスク処理を行う作業ノートの一覧を得る。
以降の処理は、対象となる各作業ノートに対して行う。
## 4. 作業ノートから`#プロジェクト名`のツリーを抽出する
作業ノートをMarkdown構造で解析し、箇条書きツリーから対象プロジェクトの `#プロジェクト名`（例: `#今世は悪女`）以下のブロックを抽出し、取得する。
## 5. 抽出ブロックの各ノードに行頭IDを振る
抽出した箇条書きツリーのすべてのノードの、**タグを含まない行**の先頭に、連番でID（[ID: 001], [ID: 002]……）を挿入する。
IDは**作業ノート1件ごとにリセット**する（複数の作業ノートを跨いで連番にはしない。ステップ8「呼び出し粒度の原則」で1作業ノート＝1リクエストとしているため、IDのスコープもノート単位に揃える）。

例：
```
- #今世は悪女 
	- #1話 
		- #初稿
			- [ID: 001] 主人公の前世の思い出からスタート。
			- [ID: 002] 処刑までの流れをダイジェストで。
```
## 6. 文脈理解テキストを取得する
プロジェクトの文脈理解テキストとして以下を利用する。
- プロジェクト管理ノート

上のノートの全文（※箇条書きを含めた自由文すべて）を取得する。
## 7. プロンプトを作成する
抽出した作業ノートのブロックと、文脈理解テキストを用いて、プロンプトを作成する。
プロンプトテンプレートには`prompts/cull_settings.txt`（プレーンテキスト形式）を用いる。
変数の埋め込み方式は[[スポット/Pythion開発/（旧）共通設定・モジュール仕様#5 プロンプトテンプレートの変数埋め込み方式|プロンプトテンプレートの変数埋め込み方式]]（`%%トークン名%%`＋`str.replace()`）に従う。

```
<reference_data>
%%CONTEXT_TEXT%%
</reference_data>

<working_text>
%%WORKING_TEXT%%
</working_text>

<instructions>
あなたは校正・文章解析アシスタントです。
<working_text> の内容を分析し、<reference_data> の内容と【関係がない記述・逸脱している内容】を抽出してください。

# 出力のルール
<working_text> 内から、<reference_data> に記載されたテーマ・設定・文脈と関連しない行を抽出し、行頭ID（[ID: *]）の番号だけを対象としてください。
行頭IDがない行は文脈判定の対象外です。
挨拶やそれ以外のコメントは一切不要です。

# 出力形式
以下のJSON形式でのみ出力してください（前後に説明文を付けないこと）。
{"unnecessary_ids": [2, 7, 12]}
（IDは整数として返すこと。ゼロ埋めしない。該当なしの場合は空配列 {"unnecessary_ids": []} を返すこと。）
</instructions>
```
## 8. AIへの問い合わせを行う
[[スポット/Pythion開発/（旧）共通設定・モジュール仕様#AI問い合わせモジュール（`ai_client.py`）|AI問い合わせモジュール]]を通じてAIへの問い合わせを行い、作業ノートのうち**不要と判断されたテキスト**の行頭ID（不要行のID）を配列で返させる。
- 1つの作業ノートにつき1回のリクエストにまとめ、同一ノートに対して複数回問い合わせないこと（[[スポット/Pythion開発/（旧）共通設定・モジュール仕様#1 呼び出し粒度の原則|呼び出し粒度の原則]]参照）。
- 対象作業ノートの`updated`フィールドが前回実行時から変わっていない場合は、[[スポット/Pythion開発/（旧）共通設定・モジュール仕様#キャッシュモジュール（`cache.py`）|キャッシュモジュール]]によりAIへの再問い合わせを省略すること。
## 9. 不要ノードを削除・転記する箇条書きツリーを作成
### 1. 不要行の有無の確認
JSON配列（`unnecessary_ids`）が空であれば、タスクを終了する。
### 2. 不要行ID配列との照合
箇条書きツリーから不要なノードを削除しつつ、転記用の箇条書きツリーを生成する。
#### 1. 転記用の箇条書きツリーを生成
転記用に、新たに`#作業フォルダ名`（例：`#1話`。転記元の作業ノートが属する作業フォルダ名のタグ）を最上位とする箇条書きツリーを生成する。
#### 2. 不要行IDの配列と照合
箇条書きツリーの先頭から順番に、行頭IDを不要行IDの配列と照合し、以下の処理を行う。

- ノードに行頭IDが振られていない場合
	- 何もしない
- 行頭IDと同じナンバーが不要行IDの配列にあった場合
	1. 該当ノードと**その下のノード（子や孫を含めたブロック）** をまとめて抽出する（**子・孫ノード自身の行頭IDが不要行ID配列に含まれているかどうかに関わらず、親ノードの判定結果を優先し、まとめて転記対象とする**）
	2. 転記用ツリーに、`#作業フォルダ名`の子ノードとして、インデントを揃えつつ追記する
	3. 箇条書きツリーから、該当ブロックをまとめて削除する
- 行頭IDのナンバーが不要行IDの配列にない場合
	- ノードの行頭IDを削除する
## 10. 転記先デイリーノートを特定する
実行日の前日を起点に、日付を1日ずつ遡りながらデイリーノートの存在を確認し、**最初に存在が確認できた日付**のデイリーノートを転記先とする。
- `max_lookback_days`で指定した日数分遡っても既存のデイリーノートが見つからない場合は、エラーとしてログに出力し、当該プロジェクトの処理を中断する。
## 11. デイリーノートの末尾に追記する
1. 転記先デイリーノートに`#プロジェクト名`のツリーがあるかを確認する。
	1. なければ、ノート末尾に`#プロジェクト名`を親とするツリーを新たに作る。
2. `#プロジェクト名`の子に、転記元の作業フォルダ名と同名の`#作業フォルダ名`ノードが既に存在するかを確認する。
	1. 存在する場合：そのノードの子として、転記用ツリーの中身（`#作業フォルダ名`直下のブロック群）を追記する（`#作業フォルダ名`ノード自体は重複作成しない）。
	2. 存在しない場合：転記用ツリーの`#作業フォルダ名`ノードを、`#プロジェクト名`の子としてそのまま追記する。
3. 追記・作成した`#作業フォルダ名`ノードに、転記元へのリンクと`#skip_tag`を付与する（既に付与済みの場合は付与し直さない）。（フォーマット：`#作業フォルダ名 ◀ [[作業ノートへのリンク]] から #skip_tag`）

※本ステップを先に実行し、ステップ12（作業ノート側の書き換え）を後に実行すること。デイリーノート側への追記は`#skip_tag`によって重複追記が検知可能（[[Utilities/Documents/詳細設計/執筆タスク/デイリーノートから作業・設定ノートへの自動転記|デイリーノートから作業・設定ノートへの自動転記]]参照）だが、作業ノート側の削除には同等の再実行安全性がないため、より安全な操作（追記）を先に、より危険な操作（削除）を後に行う。
## 12. 作業ノートの箇条書きツリーを入れ替え
作業ノートから箇条書きツリーを削除し、不要行を削除したツリーを新たに追記する。
### 実行・安全規定
- 人手による確認フェーズは設けない。`execute`ではAI判定後、デイリーノートへの転記と作業ノートからの削除を連続実行する。
- `dry_run`ではAI判定と変更予定の出力まで行い、転記・削除しない。
- AI通信エラー、JSONパース失敗、存在しないID、重複ID、対象の一意性不足がある場合は当該作業ノートを変更しない。
- 転記元・転記先について書き込み直前の競合確認とスナップショット取得を行う。
- デイリーノートへの追記を再読込して検証した後にのみ、作業ノートから削除する。
- 後続削除に失敗した場合は、競合がなければ処理単位全体を復元する。競合があれば自動復元せず中断する。
- 再実行時はデイリーノート側の転記元リンクと`#skip_tag`を確認し、同一転記の重複追加を防ぐ。
