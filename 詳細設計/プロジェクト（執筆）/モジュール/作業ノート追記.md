# 対象モジュール
- `modules/project_types/writing.py`
# インターフェース
`append_to_work_note(project_context, destination_path, source_path, source_block, destination_tag, mode)`
# 前提条件
転記先作業ノートは事前の検出処理で以下を満たしているものとする。
- `type: 作業ノート`
- `status: true`
- 該当する作業フォルダ内で一意に特定されている。
- Frontmatter検証に成功している。
- 書き込み禁止対象に該当しない。
作業フォルダが`Chapters/完了/`以下に存在するかどうかは転記可否に使用しない。
# 1. 転記対象ブロックをコピーする
転記元の`destination_tag`を含むノードを起点として、子孫を含むブロック全体を階層構造を保持したままコピーする。この時点では転記元を変更しない。
# 2. 転記先タグのノードを除去する
コピーしたブロックの最上位から、作業ノートの検出に使用した`destination_tag`を含むノードだけを除去する。その子ノードを1階層引き上げ、追記対象とする。
```markdown
- #1話
  - #プロット
    - 主人公の前世の説明から始める
  - #メモ
    - 冒頭のテンポを再検討する
```
上記は次の2ブロックへ加工する。
```markdown
- #プロット
  - 主人公の前世の説明から始める
- #メモ
  - 冒頭のテンポを再検討する
```
# 3. 追記単位へ分割する
転記先タグ直下の各ノードを個別の追記単位として扱う。処理順は転記元での出現順を維持する。
# 4. 基準ツリーを特定する
転記先から`#プロジェクト名 > #作業フォルダ名`の基準ツリーを完全一致で検索する。
- 0件：必須構造不足としてERROR。書き込みを中止する。
- 1件：処理を継続する。
- 2件以上：一意性ERROR。書き込みを中止する。
基準ツリーは本処理で自動生成しない。
# 5. 追記単位のセクションタグを取得する
各追記単位の最上位ノードからタグを抽出する。
- タグ0件：`fallback_section`を使用する。
- タグ1件：同名セクションの候補とする。
- タグ2件以上：各タグから解決したセクションパスを重複排除し、1件に確定できた場合だけ使用する。0件または2件以上なら当該追記単位をスキップする。
# 6. 同名セクションを検索する
基準ツリー配下から、セクションタグと同じタグを持つノードを完全一致で検索する。
- 0件：フォールバックへ進む。
- 1件：該当セクションを追記先とする。
- 2件以上：当該追記単位をスキップする。
出現順、階層の深さ、更新日時で自動選択しない。
# 7. フォールバック先を特定する
基準ツリー直下から`#fallback_section`を完全一致で検索する。
- 0件：基準ツリー直下に`#fallback_section`を新規作成する。
- 1件：該当ノードを使用する。
- 2件以上：一意に特定できないため当該追記単位をスキップする。
# 8. 追記ブロックを加工する
- 同名セクションへ追記：追記単位の最上位セクションタグを除去し、その子孫だけを追記する。
- フォールバックへ追記：元の分類を失わないため、最上位ノードを含むブロック全体を追記する。
- 最上位にタグがない：追記単位全体をフォールバックの子として追記する。
# 9. インデントを調整する
転記先ノートの既存インデント形式を使用し、子孫間の相対階層を維持して追記先セクションの末尾へ配置する。既存ブロックの並べ替えや一括整形は行わない。
# 10. 追記計画を作成する
全追記単位について追記位置、加工後ブロック、フォールバック適用有無、スキップ理由をメモリ上で確定する。同一セクションへの追記は元の出現順を維持する。
# 11. 競合確認と書き込みを行う
1. 書き込み直前に転記先の`updated`を再確認する。
2. 競合があれば書き込みを中止し、自動マージしない。
3. `dry_run`では追記計画だけをログへ記録し、スナップショットと書き込みを行わない。
4. `execute`ではスナップショット取得後、全追記単位を反映した内容を1回だけ書き込む。
5. 書き込み時にFrontmatterの`updated`を更新する。
# 12. 書き込み結果を検証する
再読込後、予定したブロックの存在、階層構造、Frontmatter、`updated`を検証する。失敗時は安全に復元できる場合に限りスナップショットから復元する。
# 13. 処理結果を返す
少なくとも以下を返す。
- 処理の成否
- 転記先パス
- 追記したセクション一覧
- 追記ブロック数
- スキップした追記単位と理由
- フォールバックの適用有無
- 書き込み後検証の成否
呼び出し元は、転記先の書き込み後検証が成功した場合に限り、転記元へ`#skip_tag`を付与する。転記元更新に失敗した場合は、[[Utilities/Documents/詳細設計/モジュール/ファイル安全管理|ファイル安全管理]]の複数ファイル更新規定に従う。
